МОТИВАЦИЯ:

Проблемы:
- Заказы теряются между системами
- Не видно где заказ "застрял"
- Долгая диагностика инцидентов

Метрики, на которые повлияет трейсинг:
| Метрика                      | Влияние      |
|------------------------------|--------------|
| MTTR (время восстановления)  | Уменьшится   |
| Количество потерянных заказов| Уменьшится   |
| Время диагностики инцидента  | Уменьшится   |
| Customer satisfaction        | Увеличится   |
| Revenue loss                 | Уменьшится   |


СИСТЕМЫ ДЛЯ ПОКРЫТИЯ:

Критичные точки (где заказ может сломаться):
1. Shop API → RabbitMQ (отправка заказа)
2. RabbitMQ → CRM API (получение заказа)
3. CRM API → RabbitMQ → MES API (передача на расчёт)
4. MES API (расчёт стоимости — долгая операция)
5. MES API → RabbitMQ → CRM API (изменение статуса)


ДАННЫЕ В ТРЕЙСИНГЕ:

| Поле             | Назначение                    |
|------------------|-------------------------------|
| trace_id         | ID всей цепочки               |
| span_id          | ID текущей операции           |
| parent_span_id   | ID родительской операции      |
| order_id         | Correlation ID (бизнес-ключ)  |
| service_name     | Название сервиса              |
| operation_name   | Название операции             |
| timestamp        | Время начала                  |
| duration         | Длительность                  |
| status           | OK / ERROR                    |
| error_message    | Текст ошибки (если есть)      |


ПРЕДЛАГАЕМОЕ РЕШЕНИЕ:

Технологии:
- OpenTelemetry SDK — инструментация кода
- Jaeger — сбор, хранение, визуализация трейсов
- Correlation ID — order_id пробрасывается через все системы

Новые компоненты:
- Jaeger Collector — приём трейсов
- Jaeger Query + UI — визуализация
- OTel exporter в Shop API (Java)
- OTel exporter в CRM API (Java)
- OTel exporter в MES API (C#)

См. диаграмму: c4-tracing.drawio


КОМПРОМИССЫ:

| Аспект                | Компромисс                              |
|-----------------------|-----------------------------------------|
| Производительность    | Overhead ~1-3% на инструментацию        |
| Хранение              | Трейсы занимают место (retention 7-14d) |
| Полнота данных        | Sampling при высокой нагрузке           |
| Сложность внедрения   | Нужно доработать все 3 API              |


БЕЗОПАСНОСТЬ:

- Доступ к Jaeger UI только для сотрудников (SSO/LDAP)
- Роли: Support (read-only), Developer (read), Admin (full)
- Не логировать PII (имена, email, телефоны клиентов)
- Jaeger UI за VPN или internal network
- TLS для передачи трейсов


АВТОМАТИЧЕСКИЙ МОНИТОРИНГ (доп):

На основе данных трейсинга:
- Алерт: заказ в статусе SUBMITTED > 1 часа (застрял на расчёте)
- Алерт: span с status=ERROR
- Дашборд "застрявших" заказов по статусам
- Метрика: среднее время прохождения заказа по этапам

См. диаграмму с алертингом: c4-tracing.drawio (вкладка 2)

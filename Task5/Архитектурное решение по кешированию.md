ПРЕДЛАГАЕМОЕ РЕШЕНИЕ:

Тип: Серверное кэширование (Redis)
Паттерн: Cache-Aside

Сравнение паттернов:
| Cache-Aside        | Read-Through           | Write-Through        | Refresh-Ahead          |
|--------------------|------------------------|----------------------|------------------------|
| + Простая реализ.  | + Чистый код           | - Избыточен          | - Сложная реализация   |
| + Redis из коробки | - Нужен доп. слой      | - Пишем редко        | - Предсказуемый доступ |
| + Полный контроль  | - Hazelcast/Ignite     | - Синхронная запись  | - Фоновое обновление   |
| = Выбран           |                        |                      |                        |


СТРАТЕГИЯ ИНВАЛИДАЦИИ:

| По ключу              | TTL                  | Комбинированная           |
|-----------------------|----------------------|---------------------------|
| Точечная инвалидация  | Простая              | Лучший выбор              |
| Нужна логика в коде   | Данные устаревают    | По ключу + TTL fallback   |

Выбор: Комбинированная (по ключу + TTL 5 мин)
- При изменении статуса — инвалидация по ключу
- TTL 5 мин — защита от рассинхронизации

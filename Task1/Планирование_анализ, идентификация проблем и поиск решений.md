ПРОБЛЕМЫ:

1. Потеря заказов между системами

2. Отсутствует мониторинг

3. Производительность MES:
   - медленный dashboard
   - долгий расчёт стоимости (2-30 мин)

4. Инфраструктурные:
   - Один инстанс каждого API-сервиса
   - Один инстанс каждой базы данных
   - Один RabbitMQ без кластеризации

5. Процессы:
   - ручное тестирование
   - ручной деплой на прод


ИНИЦИАТИВЫ (по приоритету):

1. Observability (логи, метрики, трейсы)
2. Надёжность RabbitMQ (DLQ, retry)
3. Оптимизация MES dashboard (индексы, кэш)
4. Горизонтальное масштабирование API
5. Read replicas для PostgreSQL
6. Асинхронный расчёт стоимости + кэширование результатов
7. Автоматизация E2E тестирования


ЦЕЛЕВАЯ АРХИТЕКТУРА (6 месяцев):

- 2+ инстанса каждого API за Load Balancer
- PostgreSQL: Primary + Read Replica
- RabbitMQ и retry policy
- Redis для кэширования
- Prometheus + Grafana + Jaeger
- Централизованные логи (ELK/Loki)


ТОП-3 ИНИЦИАТИВЫ:

1. Observability — видеть где проблемы
2. Надёжность RabbitMQ — не терять заказы
3. Оптимизация MES — быстрый dashboard для операторов
